## vs v1.3.2

- **No performance regression.** Step throughput (~12.5 M steps/s) sits
  inside the v1.3.2 band (~11–13 M steps/s); snapshot (~0.011 vs ~0.007 ms),
  print-loop (~8.4 vs 5–7 ms), and search (~0.4 ms) differences are
  run-to-run noise on the same core code (`machine.step` untouched).
- **Memory bounded.** New buffers are capped: folder listing (2000
  entries), highlight rows (5000 lines), folder file I/O (256 KiB). The
  largest bound remains step history (32 MiB worst case, unchanged).
- **New costs are trivial.** Highlight tokenizes the whole document per
  keystroke via `useMemo` (pure, capped at 5000 lines — classroom files are
  KBs, so no windowing needed); ALU description reads the current
  instruction + flags (microseconds, evaluated per render); folder IPC
  lists only on open/refresh/create/rename/delete.
- Watch out next time: web folder handles live in memory (not persisted) —
  a reload drops the web backend to localStorage tabs by design; consider
  File System Access persistence (IndexedDB handles) only if users ask.

## Fix round (same release)

- In-app name/confirm dialogs replace all `window.prompt/confirm` (Electron
  crash fix); open-tabs state split from project files (tab close keeps the
  file, tabs persist); Electron restores its last folder and defaults to a
  filesystem-first empty state; tooltips are custom CSS (instant) with native
  title fallback. No emulator-core changes — no re-benchmark needed.

## Fix round 2 (same release)

- Root cause for "can't create file inside new folder": extensionless/empty
  folders were misbuilt as file nodes by the path heuristic — the tree now
  honors explicit `isDirectory` flags (regression test included).
- Collapsible CPU-column sections share one header component; ZIP export is
  a dependency-free stored writer with round-trip tests. Suite now 112 pass.
  No emulator-core changes — no re-benchmark needed.
