## vs v1.3.1

- **No performance regression.** Step throughput, snapshot cost, and
  print-loop time are within run-to-run noise of v1.3.1 (same core code).
- **Memory improved.** Console is now capped (was the one unbounded
  buffer flagged in the v1.3.1 audit); per-file input is capped at 256 KiB.
- **New costs are trivial.** Watch evaluation reuses `readOperand`
  (microseconds, evaluated per render); memory search scans ≤ 64 KiB only
  on explicit Find/Next.
- Watch out next time: step history (32 MiB worst case) is now the largest
  bound — consider differential snapshots or a lower cap if mobile
  Safari memory pressure is ever reported.
