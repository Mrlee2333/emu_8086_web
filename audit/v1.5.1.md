## vs v1.5.0

- **The emulator is untouched, and the benchmark says so.** Step throughput,
  snapshot cost, print-loop cost and search all sit inside the run-to-run band
  in both directions across the three interleaved passes. There is no step-loop
  change to regress, because this version adds display code and nothing else —
  no new instruction, no new flag, no new operand path.
- **The bundle grew 9,692 B, and all of it is the new view.** The register
  Details dialog, the per-register `i` button and the value breakdown are one
  component in `cpu-panels.tsx`, which is on the IDE path for every user, plus
  `lib/ide/reg-info.ts` — a table of thirteen purpose sentences and a few
  format helpers. The strings are the bulk of it: 9.6 KB of first-load JS to
  hold 13 sentences that are behind a button is the honest trade for the
  feature, and the budget gate still passes with 27.6 KB to spare. Worth
  watching: at 96.2 % of budget this is now the tightest the `/` route has
  been, so the next feature that lands here should be reviewed for size.
- **The measure that matters for this change is not in the table above.** A
  register display is either right or it is quietly wrong, and a benchmark
  cannot see that. The 28 new tests in `lib/ide/reg-info.test.ts` check the
  high and low byte against `Machine.get8` on real machine state after
  `MUL`, `DIV`, `XLAT`, `AAM` and `AAD` — the instructions that leave AX or DX
  holding a value whose two bytes mean different things. A test that set
  `ax = 0x1234` and expected `BE`/`34` would pass with the halves swapped;
  these would not, because a swapped high byte survives `MUL AL, 07h`
  (which writes `AX = 0021h`, where both bytes are `21`) and fails on
  `MUL AL, 40h` (which writes `AX = 0140h`).
- **A review round found eight defects, all of them in the text and the
  formatting rather than the emulator.** The most interesting was a byte's
  binary grouped in twos — `AH` read `00 10 00 11` instead of `0001 0011`,
  which looks like four separate values rather than one eight-bit one. The
  16-bit grouping was always correct, so no test written against `AX` alone
  could ever have found it, and the compact panel was not displaying byte
  binary at all, which is why nobody saw it. It is displayed now, so the fix
   is observable rather than latent. The rest were claims about the 8086 that
   were confidently wrong: CX is not half of `DX:AX`, BX is not a string-op
   base, a plain `MOVSB` does not decrement CX, `RET` restores IP as well as
   `IRET`, `AAD` is unpacked BCD where `DAA`/`DAS` are packed, and `LES`/`LDS`
   take any memory operand. Each correction now has a test that runs the
   emulator rather than trusting the sentence, because a plausible-sounding
   description is exactly the kind of thing that rots unnoticed.
- **A re-review caught the correction introducing a new falsehood.** Fixing
   "CX is the high half of `DX:AX`" by describing it as the low half of the
   `CBW`/`CWD` pair was wrong in the same way: `CBW` sign-extends `AL` into
   `AX`, only `CWD` writes `DX`, and neither instruction touches `CX` at all.
   The underlying mistake was the test's shape — it asserted that the *old*
   wording was absent, which guards a string rather than a fact, so any
   replacement passed. The tests now run the instructions and check the
   registers, which is why the second wording was caught and the first was not.
- **No memory bound moved.** Nothing new is retained across a run: the
  descriptions are module-level constants and the open-strip state is one
  `{name, show}` object in React state.

## What changed, and what it cost

| Change | Cost |
|---|---|
| `lib/ide/reg-info.ts` | Pure. 13 descriptors per render of the panel, no allocation retained |
| Register Details dialog | Renders only when open; closed it costs one `useState` |
| `i` button and value strip | One extra row under the grid, shown for one register at a time |
| Per-instruction notes | A `Record` lookup on a key the panel already had |
## Reproduce

```sh
bun audit/bench.mjs --runs 15                 # this version
git worktree add /tmp/emu150 v1.5.0           # the previous version
cd /tmp/emu150 && bun install && bun audit/bench.mjs --runs 15
bun test lib electron
bun run verify
```

Note: the baseline worktree needs its own `bun install`. Symlinking
`node_modules` from the main checkout fails the build — Turbopack rejects a
symlink that points out of the filesystem root — so the worktree gets a real
install.
